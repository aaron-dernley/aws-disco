# AWS Architecture Diagram

A weekly, animated D3 architecture diagram of an AWS region — every compute
object and every network route in and out — generated by a swamp workflow.

```bash
swamp workflow run '@adernley/aws-disco/diagram' --input region=eu-west-2
open diagrams/aws-architecture-eu-west-2.html
```

The output is a single self-contained HTML file with D3 embedded. It opens
offline, so it can be attached to an email or dropped in Slack as-is.

## What it draws

- **Boundaries** — VPCs contain subnets, each labelled with its AZ, CIDR and
  whether it is public. Public means the subnet's route table actually reaches
  an internet gateway, not just that `MapPublicIpOnLaunch` is set.
- **Compute** — EC2 instances, auto scaling groups, ECS clusters and services,
  EKS clusters and node groups, Lambda functions.
- **Edge** — load balancers, listeners and target groups.
- **Inbound routes** — internet → internet gateway → internet-facing load
  balancer → listener port → target group → the compute behind it.
- **Outbound routes** — read from real route table entries, not inferred: via
  NAT gateway, directly out of a public subnet, across a VPC peering
  connection, or to an AWS service through a VPC endpoint.

Interactions: drag nodes, scroll to zoom, click any object to pin it and see
every path in and out, and use the left rail to filter by object category, path
type or boundary. Amber dashes are traffic that crosses the internet; cyan dots
stay inside AWS. Particles animate along each path in the direction of travel.

## How it is built

Five models and one workflow.

| Model | Type | Purpose |
| --- | --- | --- |
| `aws-network` | `@swamp/aws/ec2/vpc` | VPCs, subnets, route tables and routes, gateways, endpoints, peerings, security groups, ENIs |
| `aws-compute` | `@swamp/aws/ec2/instance` | EC2 instances, auto scaling groups, launch templates |
| `aws-workloads` | `@swamp/aws/ecs/cluster` | ECS clusters and services, EKS clusters, Lambda functions |
| `aws-edge` | `@swamp/aws/elasticloadbalancingv2/load-balancer` | Load balancers, listeners, target groups |
| `aws-diagram` | `@adernley/aws-architecture-diagram` | Renders the inventories into the HTML diagram |

The first four are the **official** `@swamp/aws/*` types, extended in place via
`export const extension` with a `discover` method
(`extensions/models/aws/*_discover.ts`). Each `discover` is a single fan-out
call that inventories its whole domain, so the model takes its lock once instead
of being hit with one call per resource.

The four discovery models run concurrently in the workflow's `discover` job;
`render` then reads their output through CEL — `data.latest("aws-network",
"inventory").?attributes` — so nothing is fetched twice.

### Why a `discover` method had to be added

Every `@swamp/aws/*` type is an auto-generated CloudControl CRUD wrapper
exposing exactly `create`, `get`, `update`, `delete` and `sync`. `get` takes one
identifier; there is no list, search or discover anywhere in the family, and
`@swamp/aws/resourceexplorer2` only wraps Resource Explorer's own config
resources rather than its search API. Extending the official types was therefore
the right move under "extend, don't be clever" — and the extensions reuse the
exact dependency the official ones already pin
(`npm:@aws-sdk/client-cloudcontrol@3.1090.0`), adding no new client surface.

Two CloudControl quirks shaped the implementation:

- **`ListResources` is thin.** For VPCs, route tables, security groups and
  gateways it returns nothing but the primary identifier, so discovery runs a
  bounded-concurrency `GetResource` hydration pass to fetch CIDRs, rules and
  route targets. This is most of the runtime.
- **Some children need their parent.** Routes, subnet associations, ECS services
  and ELB listeners will not list without parent context, so discovery expands
  them per parent and then deduplicates — asking 47 route tables for their
  subnet associations returns the same set 47 times.

Known gaps, recorded in the diagram footer rather than hidden: network ACL
entries have no CloudControl LIST handler, and ECS task definitions are skipped
because ECS lists every historical revision (each service reports the revision
it actually runs, which is the one that matters).

## Weekly schedule

The workflow declares its own trigger:

```yaml
trigger:
  schedule: "0 6 * * 1"   # Mondays, 06:00
  inputs:
    region: eu-west-2
```

### Credentials

This is the one thing to get right before relying on the Monday run. The
discovery models use the standard AWS credential chain. Short-lived `ASIA…` STS
credentials in environment variables expire in about an hour, which is shorter
than nothing — a full run takes roughly 12 minutes and credentials expired
mid-run three times while this was being built.

For the scheduled job, use something that renews itself: an instance role, an
ECS task role, or a profile backed by `credential_process`/SSO. Alternatively
store long-lived keys in a vault and wire them into the discovery model
definitions:

```yaml
globalArguments:
  accessKeyId: ${{ vault.get("aws", "ACCESS_KEY_ID") }}
  secretAccessKey: ${{ vault.get("aws", "SECRET_ACCESS_KEY") }}
```

The workflow guards against a silent half-failure: discovery steps are
`allowFailure: true` so one bad domain still yields a diagram, but a `freshness`
assert fails the run if any domain served data older than the freshness window.
Without it a run with expired credentials would quietly redraw last week's
topology and present it as current.

### Another region

Nothing is region-specific:

```bash
swamp workflow run '@adernley/aws-disco/diagram' --input region=eu-west-1
```

This writes `diagrams/aws-architecture-eu-west-1.html`. The region flows from
the workflow input into each `discover` call and into the diagram's title and
filename.

## Repository layout

```
extensions/models/aws/
  _lib/cloudcontrol.ts      CloudControl list/get, retry, hydration
  _lib/inventory.ts         Shared inventory schema and discovery driver
  _lib/topology_graph.ts    Inventories -> nodes, links, boundaries
  _lib/diagram_template.ts  The standalone HTML, CSS and D3 client
  network_discover.ts       } `export const extension` — adds `discover`
  compute_discover.ts       } to the official @swamp/aws types
  workload_discover.ts      }
  edge_discover.ts          }
  architecture_diagram.ts   `@adernley/aws-architecture-diagram` model
workflows/
  workflow-aws-architecture-diagram.yaml
diagrams/
  aws-architecture-<region>.html
```

